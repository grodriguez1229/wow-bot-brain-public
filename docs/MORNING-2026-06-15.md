## "Default replies" diagnosis (2026-06-15) — why bots sometimes sound canned
The brain is healthy and DOES return real, in-character replies (verified). The canned
ones come from TWO engine-built-in chat systems that run ALONGSIDE the LLM:
1. **Whisper `HandleCommand` fallback** (`Script/Playerbots.cpp:218`): every real-player
   whisper is routed to the LLM (`PostChat`, line 215) AND to `HandleCommand`. When the
   whisper isn't a recognized command, the command path can still emit canned text. The
   canned reply is synchronous so it can land before the async LLM reply.
2. **`SayAction` smalltalk** (`Ai/Base/Actions/SayAction.cpp:~692`, "i dont know what" /
   "who cares" / etc.), driven by the built-in chat-reply system gated by
   `AiPlayerbot.RandomBotTalk=1`. This is independent of the LLM and produces canned
   ambient + reply lines.

### Fix (chosen approach: keep whisper commands, suppress canned for non-commands)
- **Whisper path:** in `OnPlayerCanUseChat` (whisper), keep `HandleCommand` for RECOGNIZED
  commands but skip its canned FALLBACK when the message is natural language handled by the
  LLM. Cleanest implementation: gate the unrecognized-command fallback replies (the
  `"warning"` push at `PlayerbotAI.cpp:821` and the SayAction smalltalk fallbacks) so they
  no-op when `sLlmBridge.IsEnabled()`. Commands still execute; non-commands go LLM-only.
- Needs the same worldserver rebuild as guildinvite. Verify at build time (can't test
  without the binary).
- **NO-REBUILD lever to try first:** set `AC_AI_PLAYERBOT_RANDOM_BOT_TALK: "0"` in
  docker-compose.override.yml + recreate worldserver. This disables the built-in SayAction
  canned chat while LEAVING the LLM `/tick` ambient + LLM whisper replies intact (those are
  the LlmBridge's own paths, not gated by RandomBotTalk). Should remove most canned
  smalltalk with no rebuild. (Recreate kicks anyone online — do it when not logged in.)
  The whisper HandleCommand fallback would still need the C++ fix.
