# R9 Friends Who Remember You Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bots earn friendship with real players through shared play, remember concrete shared
moments, and a friend who is online may whisper the player 20-120 s after login (callback,
invite or check-in) in a short, human voice.

**Architecture:** The C++ bridge posts game events (login, logout, group roster, instance
enter, boss kill, death, level-up) to a new brain endpoint `/event`. The brain turns them into
a shared-history store (`play_sessions`, `shared_events`, `moments`, `player_seen`) that R10
can read, and into familiarity points (play-driven, chat capped, decaying). On `login` the brain
plans at most 2 whispers, generates them grounded only in stored history, and returns them in
the `/event` response with `delay_s`; the C++ queues each with a due time and delivers it as a
real whisper (plus a real group invite for the invite kind). The `/chat` and `/heard` lanes get
R8-style shapes, no self-intros, no emote actions, and their own model knob for a 14B A/B.

**Tech Stack:** Python 3 / FastAPI / SQLite / pytest (brain); C++ AzerothCore module scripts
(mod-playerbots LlmBridge); Ollama on GusDesktop.

**Spec:** `docs/superpowers/specs/2026-11-03-r9-friends-design.md` (binding). Read it with this plan.

## Review Focus

1. **Cross-faction friend.** An Horde bot with high familiarity to Alliance Abril must never be picked: in-game cross-faction whispers fail. Pinned in Task 9 (`test_cross_faction_friend_never_planned`).
2. **Missed logout / sidecar restart leaves sessions open.** The next `login` must close them at the player's `last_seen`, not at now, so a crash does not mint a 3-day "long session". Pinned in Task 5 (`test_login_closes_stale_sessions_at_last_seen`).
3. **Relog spam.** Logging out and in twice within minutes must not produce a second round of whispers from the same bot. Pinned in Task 9 (`test_pair_cooldown_blocks_relog_whisper`).
4. **Friend goes busy or offline between planning and delivery.** Brain skips bots whose last tick is `in_combat`/`dead` or older than the online window; C++ drops a queued brain-initiated whisper if the target is offline, the bot's group is full (invite kind), or it is more than 600 s past due. Pinned in Task 9 (`test_busy_or_stale_bot_not_planned`) and Task 13 verification.
5. **Unknown or malformed events.** An event for a player with no history, an unknown `type`, or a missing `group` returns 200 `{"whispers": []}` and writes nothing harmful; `type: "ping"` writes nothing at all. Pinned in Task 6 (`test_unknown_and_ping_events_are_noops`).

## `/event` contract (shared by Tasks 6, 10, 13, 14)

Request (all fields optional except `type`, `player`):

```json
{"type": "login|logout|group|map|boss_kill|died|level_up|ping",
 "player": "Abril", "level": 10, "faction": "Alliance", "zone": "Teldrassil",
 "instance": "Wailing Caverns", "group": ["Astianon", "Lelindea"],
 "boss": "Mutanus the Devourer", "who": "Astianon"}
```

- `group`: names of **bots** in the player's group right now (excludes the player; `[]` = solo). Every event carries the current roster.
- `instance`: map name when the player is inside a dungeon/raid map, `""` on the overworld.
- `died`: `who` is the member who died (player or bot); `boss` is the dead member's current victim if it is a dungeon boss, else omitted.

Response: `{"whispers": [{"bot_name": "Astianon", "whisper_to": "Abril", "message": "yo wc again?", "channel": "WHISPER", "actions": [{"type": "invite", "target": "Abril"}], "delay_s": 47}]}`. Always `[]` except for `login`.

### Task 5: Presence and event ingestion

**Files:**
- Create: `presence.py`, `events.py`
- Test: `tests/test_presence.py`, `tests/test_events.py`

**Interfaces:**
- Consumes: `history.*` (Task 2), `friendship.add_play` (Task 3), `knowledge.canonical_place`, `FINAL_BOSSES` (Task 4).
- Produces (`presence.py`, in-process, `reset_state()` for tests):
  - `note_tick(bot: str, *, zone: str | None, subzone: str | None, activity: str | None, nearby_players=(), now=None) -> None`: stores state; for each nearby real player calls `events.note_copresence(bot, player, zone, now=now)`.
  - `state(bot: str) -> dict | None` (`zone, subzone, activity, ts`); `is_online(bot, *, now=None) -> bool` (`now - ts <= ONLINE_WINDOW_S`); `online_bots(*, now=None) -> list[str]`.
- Produces (`events.py`, `reset_state()` clears in-process death windows):
  - `ingest(ev: dict, *, now=None) -> None` dispatching on `ev["type"]`; unknown types and `ping` are no-ops. Every event first calls `history.note_player_seen(player, level, faction, zone)`.
  - Rules (all for each bot in `ev["group"]`):
    - `group`: open a `group` session for bots newly in the roster; close sessions of bots no longer in it (award points, below). If the player has an open run, open a run row for each newly joined bot with the same instance.
    - `map`: close the player's open runs; if `instance` non-empty and `group` non-empty, open a run per bot with `instance=canonical_place(instance) or instance`.
