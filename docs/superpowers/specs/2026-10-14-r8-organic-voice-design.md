# R8: Organic voice (design)

Date: 2026-10-14. Status: decisions made by the controller on the user's delegation ("start on a new implementation"); the user can override any ruling below.

## Problem
Bot lines are grammatical, self-contained, self-explaining sentences addressed to nobody:
"Anyone up for running Dire Maul tonight? Need some help with trash pulls if we go solo."
Real players type reactively, in fragments, with abbreviations, rarely explain, and vary wildly in
length (one word to a rambling complaint). Diagnosis: (1) the prompt asks an instruct model to
"write a line" and describes style instead of showing it; (2) almost every line opens a new topic,
bots rarely answer each other; (3) every line has the same shape/length; (4) channels are too busy.

No public corpus of real vanilla chat exists (searched 2026-10-14), so examples are hand-authored.

## Goals / acceptance (measured on 1,500 tick lines after vs `logs/r8-before-ticks.txt`)
- Median line length drops from ~68ch to <=40ch; >=25% of lines are <=20ch.
- >=25% of ambient lines are replies to another recent line in the same channel (tracked flag).
- Top 3-gram and top opener each <=3% (currently "anyone want to" 5.3%, "anyone want" 6.5%).
- R3 gains hold: IRL share <20%, emoji 0, >140ch 0, roger/copy <2%.
- Blind read: in a shuffled 40-line sample (20 before, 20 after) the after lines read as more human
  (controller judges; report the sample in the results doc).
- No new tracebacks; LLM calls per tick do not rise on average (silence/templates offset re-rolls).

## Design
1. **Example bank** (`voice_examples.py` or `voice/` data): ~40-60 ORIGINAL authored lines per
   channel (GENERAL, TRADE, LFG, GUILD, SAY) plus ~60 reply pairs (prior line -> reply). Vanilla-only
   content (cap 60, no TBC+ zones/items/classes, no DKs, no flying, no "ilvl"/"queue"/LFD).
   Realistic register: "lf1m heals sm cath", "wtb [Linen Cloth] x20", "lol", "where is mankrik's wife",
   "anyone know where the trainer is in ironforge", "ty", "omg finally dinged 40", "brb food",
   "same", "no ty", "inv pls". Tag each line with shape and optional level band.
   Per prompt, sample 8-12 examples matching channel + chosen shape, rotated (never the same set
   twice in a row fleet-wide). Instruct the model to match the examples' register but not copy them;
   post-check rejects verbatim/near copies of an example (reuse fleet dedup similarity).
2. **Shape sampler**: before generating, code picks a shape with weights per channel:
   reaction (1-3 words), short question, fragment/statement, abbreviated ad (LFG/TRADE), longer
   ramble (rare, ~10%). Each shape has a char budget (e.g. 20 / 45 / 60 / 50 / 120) passed to
   postfilter `max_len` and to `num_predict`.
3. **Reply-first**: `/tick` already receives `recent_lines`. When there are recent lines from
   OTHER speakers in the same channel (and same-faction), with probability REPLY_RATE (0.5) the bot
   replies to one (prefer questions and lines addressed to nobody yet answered). Prompt shows the
   last few lines as a chat log and asks for this person's reply. Thread depth cap 3 (track reply
   chains in-process, keyed by channel + originating line). Log `[tick] X -> CH (re Y): "..."` so
   the metric can count replies. If recent_lines are insufficient, check what the worldserver sends
   and, brain-side only, keep a fleet-wide per-channel ring buffer of emitted lines to reply to.
4. **Templates for ads**: LFG and TRADE "ad" shape is generated by code from slot templates with
   level-appropriate dungeons/items (vanilla only, by level band), with per-bot abbreviation style.
   No LLM call. Item pool must be varied (fixes the "Linen Bags" loop) with per-item fleet recency.
5. **Per-bot typing transform** (deterministic, seeded by bot name like irl_identity): caps style
   (all lowercase / sentence case / occasional caps), drop trailing punctuation rate, abbreviation
   set (u, ur, ty, np, lf, pst, prob, idk, ppl, rn), small typo rate, "lol"/"lmao" habit. Applied
   AFTER postfilter to ambient (tick + heard) lines; whispers (/chat) get a lighter version.
   Never alter item links, names, or numbers.
6. **Silence**: brain returns silence for a fraction SILENCE_RATE (0.25) of ticks before calling the
   LLM, so channels breathe and GPU load falls. Silent ticks already supported (R3).
7. **Prompt rewrite**: TICK_PROMPT framed as "here is the chat log; type your next message" with the
   examples as log lines, instead of a list of style instructions. Keep R1 grounding, R3 IRL budget
   section, action rules, and persona/who_core; trim description-of-style text that the examples
   replace.

All knobs in config.py with `WBB_` env prefix (REPLY_RATE, SILENCE_RATE, SHAPE weights if simple,
REPLY_DEPTH_CAP, EXAMPLES_PER_PROMPT).

## Out of scope
Model swap (base/raw model) and fine-tuning — user decision later. Worldserver tick interval
(C++/compose, needs recreate). R2 knowledge guard (but the example bank and templates must be
vanilla-clean).

## Metrics
Extend `eval/chatter_metrics.py`: share <=20ch, reply share (from the "(re Y)" log tag), shape mix,
top opener/3-gram. Keep existing metrics. Must parse both old and new tick log formats.
